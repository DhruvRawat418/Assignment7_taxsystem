# Team AI Use Disclosure 

Team 7 used Claude (Anthropic), OpenAI Codex, and DeepSeek throughout this assignment, and the extent and character of that assistance varied by component and by team member. AI assistance was substantial across the project: models were used to interpret the specification, design component boundaries, write and revise implementation code, generate synthetic fixtures and test suites, run development checks, and draft documentation. No member claims unaided authorship of their component. Each member remains responsible for understanding, reviewing and demonstrating the code attributed to them, and for the accuracy of the description below.

**Intake agent (Hanna Malet — Claude).**   
Claude assisted with designing and writing the interview flow, the deterministic guardrails, the input parsers, the handoff contract to the orchestrator (intake\_contract.py), the tests, the demo and the component documentation. Claude also compared the component against teammates’ interface contracts and ran the test suite. Hanna set the scope and approved the design. The offline rule parser, all tests and the demo run with no model and no API key; an optional LLM parser classifies a single redacted reply at a time, and deterministic checks run first and decide every guardrail independently.

**Eligibility & Rules agent (Jijuan Xu — Claude).**   
Claude assisted with interpreting the assignment and developing the eligibility and rules boundaries, and with drafting and revising the Python implementation, the reference corpus, synthetic fixtures, automated tests, the component demo and its documentation, and with running development checks. The component is deterministic and makes no LLM calls on the path that produces a determination. One optional classifier, scope\_sentinel, would call a model to classify free-text intake notes; it is not enabled by default, its output is constrained to reference-corpus identifiers and re-validated, and anything unverifiable escalates to a human rather than being decided. The test suite and both demo modes run with no model and no API key.

**Document Extraction agent (Xinrui Xu — OpenAI Codex).**   
Codex assisted with reading the requirements and the shared team task document, designing and implementing the extractor, writing its typed output and provenance schema and its LangGraph adapter, generating synthetic W-2 test images, and producing tests and integration documentation. Codex ran the code locally and used test failures to revise OCR label matching and the handoff loop; in a second review it added edge-case tests and corrected year/identifier classification and unreadable-amount handling, reaching 77 passing tests in a fresh isolated environment. The extractor uses RapidOCR/ONNX locally and does not use an LLM to infer tax values or perform calculations.

**Computation agent (Xiaolong Lin — OpenAI Codex).**   
Codex assisted with proposing the computation-only integration boundary, writing the typed input/output contract, implementing the deterministic MCP math server and the LangGraph-compatible computation node, drafting synthetic fixtures and tests, and writing integration documentation. IRS primary references were checked directly for 2025 rates, the Social Security worksheet rules and the senior deductions rather than accepted from a model. Tests were executed against a real local MCP subprocess and a LangGraph invocation; the implemented module calls no model API.

**Review/Audit agent, integration and dashboard (Yong Cai — OpenAI Codex).**   
Codex assisted Yong with proposing the audit boundary and drafting and revising its deterministic implementation, fixtures, tests and integration documentation, and with creating the yong/audit branch and preparing commits at his request. Codex further assisted with the LangGraph integration skeleton, provider contracts and adapters on the independent yong/integration branch, and with the dashboard workbench: case search and filtering, attention links, review/evidence/history tabs, visual styling, injection regression tests, the persistent case-service adapter and browser lifecycle, and the bounded selective-recall experiment and its usage recorder. A separate AI reviewer was used to inspect several of these changes. Codex did not rewrite teammates’ worker source files or push to their branches or main; the original extraction, computation, intake, dashboard actions, PDF exporter and Docker packaging remain attributed to their authors in commit history.

**Orchestration, dashboard integration, release verification (Dhruv Rawat, OpenAI Codex)**

**Report and documentation.**   
Claude and Codex were used to tighten, restructure and gap-check written drafts against the specification, including the introduction, conclusion and component write-ups. The technical claims and design arguments are the team’s own.

**Data handling and limits.**   
No real taxpayer records, credentials or actual Social Security numbers were supplied to any model or used in any fixture; every identifier is a 900-series test value, and no paid model call produced demo tax answers. Where synthetic demonstrations use test-only providers or tool doubles, these are explicitly labeled as such in the repository and are not evidence of live-model quality; human-interrupt demonstration responses are supplied by a test driver and are not represented as real human review. Token counts reported in docs/metrics.md are local tokenizer counts, not paid API usage.
