# SilverFile 2025 1040-SR draft export

Copy dashboard.py, pdf_export.py, requirements-pdf.txt, assets/, and the test file into the same relative locations in silverfile-app. Merge folders; do not replace existing tests or assets folders wholesale.

From the project root with its virtual environment activated:

```sh
python -m pip install -r requirements-pdf.txt
# Or, for this project's uv-managed environment:
/Users/dhruvrawat/.local/bin/uv pip install --python .venv/bin/python -r requirements-pdf.txt
python -m pytest tests/integration/test_pdf_export.py -q
python -m streamlit run dashboard.py --server.address localhost
```

Select a ready_for_human_review case. Under Download draft Form 1040-SR, click Generate draft 1040-SR, then Download filled 1040-SR draft. A separate audit-record JSON download is also available. The PDF contains the same JSON as an embedded attachment and monetary field tooltips for viewers supporting those features. The dashboard's line selector remains the portable way to inspect the evidence.

The exporter reads the latest persisted case, verifies its revision, computation freshness, audit fingerprint, and empty adversarial findings. Paused, stopped, blocked, incomplete, or stale cases cannot export. It does not invoke an LLM, recalculate taxes, change workflow state, approve a return, or file anything. Generated bytes stay in the current dashboard session until downloaded; the databases are not modified. Changing the case or revision invalidates the displayed downloads.

## Template and field handling

assets/f1040s--2025.pdf is the official four-page 2025 template supplied locally by the user. The public reference is https://www.irs.gov/pub/irs-prior/f1040s--2025.pdf. SHA-256: 162a646c25af23338d103193f1a82a058ae61f9086b41d445edfb8672d5d0072. The exporter refuses another template because field names can change between years/editions.

All 38 saved form lines are transcribed exactly with two decimal places, without new rounding or tax calculations. W-2-only line 1z is also transcribed to line 1a when its source list consists solely of document box 1 values. Filing status and the four line 12d boxes come from the validated Rules profile. Working values are excluded from the form. Missing fields are never silently assigned zero. The saved canonical field values, widget values, checkbox appearance states, and appearance streams are verified after writing. The stale alternate XFA data is removed so readers use the populated AcroForm. The output remains interactive and visibly marked DRAFT on every page.

## Scope gaps to keep visible in the team handoff

- Current intake does not collect taxpayer/spouse names or addresses. Those fields remain blank, along with taxpayer SSNs, signatures, bank instructions, refund allocation and uncollected elections. The exporter does not invent them or assume that a W-2 identity has been confirmed.
- The current pipeline escalates dependent cases. This exporter therefore does not satisfy the assignment's dependent-population requirement for those cases; the team must extend Intake/Rules and the field mapping before claiming full scope coverage.
- Existing intake assumes zero for several lines instead of collecting all permitted direct Schedule 1/2/3 inputs. PDF export faithfully reflects the reviewed result; it does not repair that upstream coverage gap.
- The PDF is the 1040-SR subset, not a generated Schedule 1-A or a filing-ready return. Uncollected fields and supporting schedules still need human/team handling.
- Stop decisions persist their workflow status, but the current stop action does not record a separate staff name/reason history. Corrections do.
- The dashboard remains a local, single-operator demo, without staff authentication or multi-user write coordination.
