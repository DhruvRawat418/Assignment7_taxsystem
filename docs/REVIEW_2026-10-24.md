# Second review of the Document Extraction branch

Historical review: the 2026-10-26 cleanup supersedes the technical-error policy
below. Model startup/inference errors now propagate to the caller instead of
returning `ocr_failed`. The data-extraction fixes remain in place.

Reviewed the actual GitHub branch after fetching it on 2026-10-24. The remote
head was `411048c` (a README edit on top of the original implementation
`c59894a`). The README edit was preserved by a fast-forward. At review time
`main` still contained only the initial README. Changes in this review remain
on `Xinrui/work`.

The original 49 tests still passed, but additional cases exposed defects. Passing
the initial suite did not mean the extractor was correct for every input.

## Findings and fixes

| Finding | Reproduced behavior before the fix | Updated behavior |
| --- | --- | --- |
| Year confused with other numbers | Box 1 `2024.00` or SSN `901-12-2024` caused an ambiguous tax year | Year evidence must be a separate non-monetary token or form-title context; amounts and identifier suffixes do not supply a year |
| Nonblank optional amount silently omitted | Box 3 `1O0.00` returned `extracted` with no box 3 fact or issue | Unreadable/unexpected nonblank content emits `invalid_amount` and blocks completion |
| Amount search could extend too far | A missing next-row anchor left the region open until a distant label | Regions always have a height cap as well as the next-row boundary |
| Unnecessary identifier requirement | A masked SSN or absent EIN prevented an otherwise usable monetary extraction | These identifiers are optional when absent; visible unsafe SSNs still reject the entire upload, and ambiguous recognized identifiers still require review |
| Nine-digit amount confused with SSN | Global SSN matching could classify an ungrouped nine-digit dollar amount as an identifier | Valid numeric tokens within labeled monetary regions remain amounts; a formatted unsafe SSN in such a region is still rejected |
| OCR initialization error crashed worker | Factory/model initialization occurred outside the error handling | The worker returns `needs_review` / `ocr_failed` without inventing facts |

Regression tests live in `tests/test_review_regressions.py`. They include real
OCR images with year-like amounts, SSNs ending in a different year, unreadable
optional content, and masked identifiers. Other tests check a missing year,
large amounts, distant unrelated numbers, unsafe formatted SSNs, and OCR failure.

## Assignment alignment

- W-2 image -> typed box facts with per-value evidence is implemented.
- Extraction does not interpret 1040-SR lines, give advice, file a return, or add
  monetary amounts. Rules/Computation retain those responsibilities.
- Intake remains responsible for calling the user-entry SSN validator before
  persistence and for linking uploads to the taxpayer/spouse. Optional document
  identifiers do not establish ownership or bypass those checks.
- Parallel extraction and a reducer are demonstrated. The complete supervisor
  still needs to connect them to the other five roles and the draft/dashboard.
- The extraction HITL example is a real interrupt/resume demonstration, not the
  full assignment's complete taxpayer eval case or persistent production workflow.

from the package cache, without inheriting the original virtual environment's
