# Audit Component Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Yong's standalone, fail-closed deterministic Audit component on yong/audit.

**Architecture:** An async Python node owns only audit_result. It validates the existing computation contract, resolves document sources through explicit bindings to Extraction, and independently builds the expected computation recipe before calling an injected trusted MCP client. No teammate code is merged and no global graph is imposed.

**Tech Stack:** Python 3.11+, standard library; unittest; optional team MCP client and LangGraph at integration time.

**Spec:** docs/superpowers/specs/2026-10-26-audit-design.md

## Global Constraints

- Never modify the incoming return, provide tax advice, clear human blockers or file anything.
- Missing evidence or unavailable tools must never become passed.
- Do not execute arbitrary tool names supplied in a recorded trace.
- No model arithmetic and no tax formulas in the audit agent; compare values with Decimal.
- Keep fixtures synthetic and logs free of raw SSNs, document contents and credentials.
- Return bounded structured issues, not raw exceptions or untrusted source text.

## Review Focus

- A forged trace that is internally self-consistent must be caught by reconstructing arguments from inputs.
- An unavailable source binding, failed OCR, or inconsistent document hash must prevent a pass.
- Duplicate IDs, dependency cycles, missing lines and bogus tool names must not crash or call tools.
- A successful prior audit must not leak into a later failed run; return fresh results and an input fingerprint.
- Tool failures and cancellation must not be hidden as approval or swallow cancellation.
